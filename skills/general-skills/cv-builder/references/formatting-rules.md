# Formatting Rules (fixed — apply without asking)

Apply these by default to any CV or application material this skill produces, in any step.

## Typography / style
- **No em dashes** anywhere. Use a period, comma, or restructure the sentence.
- **Body text in black.** Location and company name may use a contrasting grey shade for visual hierarchy — this is the one permitted exception. Everything else (role titles, bullets, summary, section headers) stays black.
- **Dates and locations right-aligned** on the same line as the role/institution, using a proper right-tab/positional-tab in docx, not manual spacing.

## Titles
- Acceptable role titles: **"UX/UI Designer"**, **"Product Designer"**, or **"User Researcher"** — use whichever best matches the actual role and the JD's own framing.

## Banned content
- **Never mention Storybook** or a Storybook handoff process, even if the JD uses the term and it's tempting to mirror it.

## Content conventions (apply if relevant to the JD/role)
- Emphasise, where genuinely applicable: Design System governance (token/semantic/component restructure), research-to-decision discipline, cross-functional influence.
- Actual handoff practice to describe accurately (Appsatile): annotated specs, component documentation pages, review of implemented work against design.
- Known reusable metrics (only if truthful and relevant): design system of 20+ UI components with 10+ variants each; unified navigation covering 4+ apps.

## Before finalizing any CV output
Check against this list as a pass. One em dash, or grey used anywhere other than location/company name, means it's not done.
